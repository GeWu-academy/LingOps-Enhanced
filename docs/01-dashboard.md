# 01 总览（Dashboard）

**入口**：登录后默认进入，或点击左侧菜单「总览」→ `/dashboard`
**接口**：`GET /api/v1/stats/dashboard`

总览是比赛时的「仪表盘」，用来一眼确认三件事：**我有没有 Shell、Flag 有没有在读、后台任务有没有卡住**。

---

## 1. 页面组成

### 1.1 顶部三个核心指标

| 指标 | 含义 | 怎么看 |
|---|---|---|
| Shell 在线 | `在线数 / 总数` | 大于 0 才有后续操作的基础；为 0 说明马被删了或网络不通 |
| Flag 读取成功 | 成功读取次数（运行中任务数会单独标注） | 数字在涨说明还在得分 |
| 运行任务 | 后台任务数量 | 突然归零要检查是否被停止/失败 |

页面每 **30 秒** 自动刷新一次，也可以点右上角「刷新状态」立即刷新。

### 1.2 六个快捷入口

点击卡片直接跳转：

| 卡片 | 描述 | 跳转 |
|---|---|---|
| 目标探测 | 扫描发现目标主机 | `/discovery` |
| Shell 管理 | 管理 WebShell 连接 | `/attack/shells` |
| 基线加固 | 批量安全加固 | `/ops/baseline` |
| Flag 读取 | 批量获取 Flag | `/flag` |
| WebShell 扫描 | 检测恶意文件 | `/defense/webshell` |
| 数据库操作 | 数据库管理 | `/ops/database` |

### 1.3 AWD 比赛流程提示

页面右侧固定展示 6 步标准流程，相当于官方推荐的操作顺序：

1. **目标探测** —— 扫描网络发现其他队伍的服务器 IP
2. **导入 Shell** —— 批量导入比赛提供的 SSH / WebShell 连接
3. **基线备份** —— 立即备份网站源码，保存原始状态
4. **安全加固** —— 执行不死马查杀、权限加固、危险函数禁用
5. **Flag 监控** —— 配置 Flag 路径，启动自动读取任务
6. **文件监控** —— 开启文件变化监控，及时发现入侵

> 比赛开局前 10 分钟按这个顺序做一遍，基本不会漏项。第 3 步的备份尤其重要：被打坏后能一键回滚。

### 1.4 安全声明

顶部横幅是法律免责声明：仅限 AWD/AWDP 竞赛与授权测试。关闭后不影响使用，但每次重新登录会再次出现。

## 2. 数据来源与统计口径

`GET /api/v1/stats/dashboard` 返回结构：

```json
{
  "code": 0,
  "data": {
    "assets":  { "total": 7, "online": 4, "offline": 3 },
    "shells":  { "total": 0, "online": 0, "offline": 0 },
    "tasks":   { "total": 5, "running": 0, "completed": 5, "failed": 0 },
    "flags":   { "total": 0, "success": 0, "running": 0 },
    "alerts":  { "total": 0, "open": 0, "critical": 0 }
  }
}
```

- `assets` 统计的是通用主机资产表（`assets`，侦察/资产登记写入，当前 UI 无独立管理页），**不是**「数据库管理」页的数据库资产（那张表是 `db_assets`，单独统计）；
- `shells` 统计 Shell 管理里的资产，`online` 取决于最近一次「测试连接」结果；
- `flags.success` 是历史成功读取次数，不是去重后的 Flag 数量；
- `alerts` 目前主要来自监控模块，未接入时恒为 0。

---

## 3. 建议的使用节奏

| 时间点 | 动作 |
|---|---|
| 开局 | 看 Shell 在线是否为 0 → 去侦察/导入 Shell |
| 每轮开始 | 确认 Flag 任务仍在运行；确认上一轮补丁已生效 |
| 每轮中 | 关注 Flag 成功数增长曲线，掉零立刻查 Shell |
| 每轮结束前 | 检查基线任务/扫描任务是否有失败，补做备份 |

---

## 4. 常见问题

**Q：Shell 显示在线，但 Flag 一直失败？**
A：在线只代表最近一次连通性测试通过。去「Shell 管理」重新测试连接，并在终端里手动执行 `id`、`ls -l /flag` 确认权限与路径。

**Q：统计数字不更新？**
A：页面 30 秒轮询一次；若长时间不动，刷新浏览器。前端部分 WebSocket 地址硬编码为 `localhost:12800`，从其他机器访问时实时推送可能失效，但 REST 统计仍会更新。

**Q：运行中任务数一直不降？**
A：到对应功能页（Flag / 基线 / 扫描）查看任务状态，必要时手动停止后重建。
