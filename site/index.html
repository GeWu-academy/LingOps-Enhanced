01

这是什么

AWD（Attack With Defense）是 CTF 的一种赛制：每队分到一批跑着有漏洞的 Web 应用的服务器， 同时要攻别人、守自己、抢 flag。真正的瓶颈从来不是「会不会打」，而是手忙不过来。

🖥️本机运行

一个跑在 127.0.0.1 的 Go 程序 + 网页控制台，所有靶机、Shell、任务、知识库集中管理，不上云。

🧩零改官方

官方只发编译好的二进制。增强全部走 index.html 注入 + assets_v2/ 静态资源，升级不冲突。

🔌零依赖

扫描后端 2844 行纯 Python 标准库。Windows 包还内置了便携版 Python 3.11，解压即用。

03

它解决哪些具体问题

每条都是「官方缺什么 → 我补了什么」，点开看细节。

侦察靶机明明活着，工具说离线▶

原因：官方侦察只发 ICMP（ping）。很多比赛环境为了防扫描把 ICMP 全 drop，靶机就全部显示「离线」。

解决：端口扫描模块用 ICMP + TCP 双栈探活 —— ping 不通就试 22 / 80 / 443 / 445 / 3389 等常见端口，只要有一个 TCP 握手成功就判定存活。实测能救回官方漏掉的大部分靶机。

侦察不知道哪个端口有上传点▶

官方没有端口扫描，更没有上传点探测。补的是一条完整链路：

存活探测 → 端口扫描（1-65535 或常用集） → 服务指纹（banner / HTTP 头）
        → Web 探测（标题 / 框架 / 路径） → 上传点探测

上传点探测会主动请求 40+ 条常见路径（/upload.php、/api/upload、/admin/upload 等），检查响应里有没有文件上传表单或 JSON 上传接口，命中的直接列出来并给出 curl 测试命令。

FlagFlag 到底在哪▶

官方 /flag 页只有一个表单，路径必须手填，默认 /flag。

Flag 查找扩展会在你已经拿到的 WebShell 上批量遍历候选路径：

  • 常见绝对路径：/flag、/flag.txt、/root/flag、/home/*/flag、/tmp/flag、/var/www/flag ……
  • 站点目录递归：搜文件名含 flag 的文件（支持 flag.php、x_flag.txt、flag.jpg）
  • Windows 路径：C:\flag.txt、D:\flag、C:\inetpub\wwwroot\flag.txt

搜到后用正则提取 flag 值（flag{...}、DASCTF{...}、32 位 hex 等），一键转成官方监控任务，之后官方那套定时读取就接管了。

AWDP官方审计扫不出漏洞（最严重）▶

官方 AWDP Break/Fix 的引擎是「污点门控 + 正则」两级：只有含 source 的行、和引用污染变量的行才进第二级跑正则。设计上压噪声，但有三个结构性漏报。

漏报 1：sink 参数里没有污点变量 → 整行不扫

system("ls -la");          // 官方不报，即使这是明摆着的命令执行
myCustomFunc2("literal");  // 同上

漏报 2：不传播二级变量

$f = $_GET['f'];      // 一级：被污染
$g = $f;              // 二级：官方引擎不传播
exec("cmd " . $g);    // 漏报

漏报 3：Go 语义引擎只覆盖文件操作。

解决：独立深度审计引擎 awdpplus.js（2078 行 / 331 条规则）做跨行污点分析：先抹掉注释和字符串（避免把文档里的 system() 当漏洞）但保留变量插值；从 source 出发沿赋值链传播到任意深度；追踪函数参数、数组元素、对象属性、sprintf / 字符串拼接；支持 PHP / Python / Node.js / Java / Go / Ruby / ASP / C# 八种语言。结果可以和官方扫描一键对比。

配套 88 个回归样本（34 真漏洞 + 27 安全写法 + 15 对抗 + 12 回归），改引擎前后各跑一遍，防止「修一个漏报换来三个误报」。

架构：扩展是怎么挂上去的

官方只发编译好的二进制和打包好的前端，没有源码。但官方前端每次请求都重新读 frontend/dist/index.html， 而 assets_v2/ 下任意文件都能被静态访问 —— 于是可以注入。

浏览器请求 / ↓ lingops-server 读 frontend/dist/index.html ↓ <html> 里多了一行： <script src="/assets_v2/lp-ext/boot.js?v=23" defer></script> ↓ boot.js 执行： ├── 往侧边栏塞「端口扫描」「ARTEX」两个菜单项 ├── 隐藏官方自带的空「团队」占位菜单 └── 点菜单 → 全屏 iframe 加载 panel.html ↓ panel.html 与主页面同源（都是 127.0.0.1:12800） → 能直接读 localStorage["lingops_token"] → 能调 /api/v1/assets 实现「从资产库导入目标」 → 能调 /api/v1/assets 把扫描结果写回资产库 ↓ 重活交给独立进程 ext/lp_scan_server.py（12801，纯标准库）

🎭为什么用 display:none 藏菜单

侧边栏是 React 渲染的。手动 removeChild 会让 React 后续卸载时抛 NotFoundError。display:none 对 React 透明，且 watchDom 会在重渲染后自动补一次。

🕳️官方菜单没有 <a href>

用 antd Menu 的 items API 渲染，输出是 <li class="ant-menu-item"><span>团队</span></li>，没有链接。选择器只能按 .ant-menu-item 的 textContent 匹配。

官方升级会覆盖注入。替换 frontend/ 后 index.html 里的注入行会消失，扩展失效 —— 重新执行注入即可（见 ext/uninstall.sh 的注释）。
